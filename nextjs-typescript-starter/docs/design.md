## 1. 现状审计

在动手设计前，必须先厘清**已有资产**与**已有障碍**。这一节是后续所有设计决策的依据。

### 1.1 已有数据库表（只读，本期不改）

#### `words` — 单词表

```sql
create table public.words (
  id bigint generated by default as identity not null,
  "wordRank" bigint null,   -- 单词在书内排名，从 1 开始
  "headWord" text null,     -- 单词本体，如 "science"
  content json null,        -- 词典详情（JSON 对象）
  "bookId" text null,       -- 所属单词书业务 ID，如 "PEPXiaoXue6_1"
  constraint words_pkey primary key (id)
) TABLESPACE pg_default;
```

#### `books` — 单词书表

```sql
create table public.books (
  id text not null,          -- 主键，形如 "book-m0abc-xyz123"
  title text null,           -- 显示标题
  "wordCount" integer null default 0,  -- 冗余词数，UI 直接读
  "coverUrl" text null,      -- 封面图 URL
  "bookId" text not null,    -- 业务唯一键，如 "PEPXiaoXue6_1"
  tags text null,            -- JSON 数组字符串 '["初中","PEP"]'
  "createdAt" timestamp with time zone not null default now(),
  "updatedAt" timestamp with time zone not null default now(),
  constraint books_pkey primary key (id),
  constraint books_bookId_unique unique ("bookId")
) TABLESPACE pg_default;

create index if not exists books_book_id_idx
  on public.books using btree ("bookId") TABLESPACE pg_default;
```

**关键约束（必须在设计中尊重）**

| 约束 | 影响 |
| --- | --- |
| `books.bookId` 是 unique 业务键 | H5 路由用 `bookId` 而非 `books.id` |
| `words.id` 是 bigint identity | 单词外键用 bigint，注意 JS number 精度 |
| `words.content` 是 **`json` 不是 `jsonb`** | **无法用 GIN 索引，无法高效 JSONB 路径查询** |
| `books.bookId` ⇋ `words.bookId` 是**弱关联，无外键** | 删书时单词不会被级联清理（后台在应用层做事务级联） |
| 表名/列名为 camelCase 且带双引号 | SQL 里必须写 `"bookId"`、`"wordRank"`，漏引号会变成小写而报错 |

> **`json` vs `jsonb` 是本项目最大的技术约束**，第 3.4、10.2 节会给出应对方案。

### 1.2 单词 content 的真实结构

源文件 `danci-admin/temp/PEPXiaoXue6_1.json` 是 **130 个 JSON 对象顺序拼接（JSONL 形态，非合法 JSON 数组）**，每个对象形如：

```jsonc
{
  "wordRank": 1,
  "headWord": "science",
  "content": {
    "word": {                          // ← 第 1 层
      "wordHead": "science",
      "wordId": "PEPXiaoXue6_1_1",    // ← 业务单词 ID
      "content": {                     // ← 第 2 层，真正要渲染的字段在这里
        "usphone": "'saɪəns",
        "ukphone": "'saɪəns",
        "usspeech": "science&type=2",
        "ukspeech": "science&type=1",
        "trans": [
          { "tranCn": "科学", "tranOther": "...", "descCn": "中释", "descOther": "英释" }
        ],
        "sentence": { "sentences": [ { "sContent": "...", "sCn": "..." } ], "desc": "例句" },
        "phrase":   { "phrases":   [ { "pContent": "...", "pCn": "..." } ], "desc": "短语" },
        "syno":     { "synos":     [ { "pos": "n", "tran": "...", "hwds": [ { "w": "..." } ] } ], "desc": "同近" },
        "relWord":  { "rels":      [ { "pos": "adj", "words": [ { "hwd": "...", "tran": "..." } ] } ], "desc": "同根" }
      }
    }
  },
  "bookId": "PEPXiaoXue6_1"
}
```

**渲染字段路径速查**（详情页直接用）

| UI 区块 | JSON 路径 | 取值方式 |
| --- | --- | --- |
| 词头 | `content.word.wordHead` | 字符串（兜底用顶层 `headWord`） |
| 业务 ID | `content.word.wordId` | 字符串 |
| 美音标 | `content.word.content.usphone` | 字符串，可为 `null` |
| 英音标 | `content.word.content.ukphone` | 字符串，可为 `null` |
| 中英释义 | `content.word.content.trans[]` | 数组：`tranCn` / `tranOther` |
| 例句 | `content.word.content.sentence.sentences[]` | 数组：`sContent` / `sCn` |
| 短语 | `content.word.content.phrase.phrases[]` | 数组：`pContent` / `pCn` |
| 近义词 | `content.word.content.syno.synos[]` | 数组：`pos` / `tran` / `hwds[].w` |
| 同根词 | `content.word.content.relWord.rels[]` | 数组：`pos` / `words[].hwd` / `words[].tran` |

> 注意 `syno` 与 `relWord` 的子字段名不同：近义词用 `hwds[].w`，同根词用 `words[].hwd` / `words[].tran`。实现时容易写错，已在第 9 节用类型固化。

### 1.4 阻塞级问题：auth.config 的全局重定向

现有 `app/auth.config.ts`：

```10:21:e:\danci\nextjs-typescript-starter\app\auth.config.ts
  callbacks: {
    authorized({ auth, request: { nextUrl } }) {
      let isLoggedIn = !!auth?.user;
      let isOnDashboard = nextUrl.pathname.startsWith('/protected');

      if (isOnDashboard) {
        if (isLoggedIn) return true;
        return false; // Redirect unauthenticated users to login page
      } else if (isLoggedIn) {
        return Response.redirect(new URL('/protected', nextUrl));
      }

      return true;
    },
  },
```

**问题**：`else if (isLoggedIn)` 分支意味着**任何已登录用户访问任意非 `/protected` 页面都会被强制跳转到 `/protected`**。这会让「登录后回到首页」「我的页」「学习页」全部失效——因为登录成功后想跳 `/` 会被立刻弹回 `/protected`。

**解决方案**：删除 `isLoggedIn` 的全局重定向分支，改为**白名单式保护**，只保护真正需要登录的路由：

```ts
const PROTECTED_PREFIXES = ["/study", "/word"];

callbacks: {
  authorized({ auth, request: { nextUrl } }) {
    const { pathname } = nextUrl;
    const needsAuth = PROTECTED_PREFIXES.some((p) => pathname.startsWith(p));
    if (needsAuth && !auth?.user) return false; // → 跳 /login
    return true; // 其余一律放行
  },
},
```

`/me` **不放入** `PROTECTED_PREFIXES`：需求要求未登录访问 `/me` 时展示登录弹窗而非跳转，交由页面自身处理（见 7.3）。

## 2. 技术选型与架构

### 2.1 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Next.js 14 App Router | 与 `danci-admin` 同代，Server Actions 可直接做数据变更，省去自建 API 层 |
| 语言 | TypeScript 5.3 | 与 admin 一致 |
| 样式 | TailwindCSS 3.4 | 移动端原子化样式，按需加载 |
| ORM | Drizzle ORM 0.29 | 与 admin 一致；`drizzle-kit` 做迁移；无外键负担 |
| 驱动 | `postgres` (postgres.js) | admin 已验证可用，配 `prepare: false` 兼容 PgBouncer |
| 鉴权 | NextAuth.js v5 beta + Credentials | 复用现有 `app/auth.ts`，仅扩展回调 |
| 密码 | `bcrypt-ts` → 建议迁 `bcryptjs` | admin 用 `bcryptjs`；`bcrypt-ts` 是原生绑定，Vercel Edge 不友好 |
| 数据库 | Supabase Postgres | 已建表，直接连 |

### 2.2 分层架构

```text
┌─────────────────────────────────────────────────────────┐
│  表现层  app/ (App Router)                               │
│  ├─ app/(tabs)/layout.tsx        底部 Tab 容器           │
│  ├─ app/(tabs)/page.tsx          首页                    │
│  ├─ app/(tabs)/me/page.tsx       我的                    │
│  ├─ app/study/[bookId]/page.tsx  学习页                  │
│  ├─ app/word/[bookId]/[wordId]/  单词详情页              │
│  └─ components/                  展示组件（Client）      │
├─────────────────────────────────────────────────────────┤
│  服务层  lib/                                          │
│  ├─ auth.ts          会话读写（复用 NextAuth）          │
│  ├─ user-guard.ts    requireUser() 守卫                │
│  ├─ progress-repo.ts 学习进度 CRUD                     │
│  └─ word-repo.ts     单词/单词书只读查询                │
├─────────────────────────────────────────────────────────┤
│  数据层  db/                                           │
│  ├─ index.ts  懒加载 Proxy 单例                        │
│  └─ schema.ts 表结构映射                                │
└─────────────────────────────────────────────────────────┘
```

**约定**：路由组件与 `lib/` 仓储全部是 Server Component / Server Action，**只有交互组件标 `'use client'`**。这样权限判断天然在服务端完成，无需在前端重复校验。

## 3. 数据库设计

### 3.1 表清单

| 表 | 归属 | 读 | 写 | 说明 |
| --- | --- | --- | --- | --- |
| `books` | 已有 | ✅ | ❌ | 单词书列表 |
| `words` | 已有 | ✅ | ❌ | 单词与详情 |
| **`users`** | 新增 | ✅ | ✅ | C 端用户（邮箱+密码），替代现有 `User` 表 |
| **`user_book_progress`** | 新增 | ✅ | ✅ | 用户 × 单词书 的学习进度 |
| **`user_word_records`** | 新增 | ✅ | ✅ | 用户 × 单词 的明细学习记录 |

### 3.2 `users` — C 端用户表

```sql
create table if not exists public.users (
  id             text primary key,                      -- "usr-<base36>-<rand>"
  email          text not null unique,                  -- 登录名，citext 忽略大小写
  "passwordHash" text not null,                         -- bcrypt，60 字符，留 255 冗余
  "displayName"  text,                                  -- 可选昵称，兜底取 email 前缀
  "createdAt"    timestamptz not null default now(),
  "updatedAt"    timestamptz not null default now()
);

-- 邮箱大小写不敏感唯一：注册 "A@x.com" 与 "a@x.com" 视为同一账号
create unique index if not exists users_email_lower_uidx
  on public.users (lower(email));
```

**为什么不用现有 `User` 表**

| 问题 | 现状 | 修正 |
| --- | --- | --- |
| 表名 | `"User"`（PG 会小写成 `user`，与关键字/保留语义混淆） | `users` |
| 邮箱唯一 | `email VARCHAR(64)` **无 unique**，并发注册会产生重复账号 | unique + lower 索引 |
| 密码列长 | `VARCHAR(64)`，bcrypt hash 恰好 60 字符，**无任何余量**，换算法即溢出 | `text` |
| 密码算法 | `bcrypt-ts`（原生绑定，Edge 运行时不兼容） | `bcryptjs`（纯 JS，与 admin 一致） |
| 审计字段 | 无 `createdAt` | 补齐 |

**迁移策略**：`User` 表当前仅有开发期测试数据，采用**新建 `users` + 一次性 `INSERT ... SELECT` 搬迁 + 保留旧表**的稳妥路径（不做 `DROP`，避免误删）。搬迁脚本见 4.4。

### 3.3 `user_book_progress` — 学习进度表

需求中的「最近学习」和「我的-学习进度」都由这张表支撑。

```sql
create table if not exists public.user_book_progress (
  id               text primary key,                    -- "ubp-<base36>-<rand>"
  "userId"         text not null
                     references public.users(id) on delete cascade,
  "bookId"         text not null,                      -- 弱关联 books.bookId，故意不加 FK
  "lastWordId"     bigint,                             -- 最近学习的单词 words.id
  "lastWordRank"   integer,                            -- 冗余排名，省一次 join
  "lastStudiedAt"  timestamptz not null default now(), -- 「最近学习」排序键
  "learnedCount"   integer not null default 0,         -- 已学单词数（预留）
  "createdAt"      timestamptz not null default now(),
  "updatedAt"      timestamptz not null default now(),

  -- 同一用户同一本书只有一条进度
  constraint user_book_progress_user_book_uniq unique ("userId", "bookId")
);

-- 「最近学习」查询：WHERE userId = ? ORDER BY lastStudiedAt DESC LIMIT 1
create index if not exists user_book_progress_user_recent_idx
  on public.user_book_progress ("userId", "lastStudiedAt" desc);
```

**设计要点**

1. **`bookId` 不加外键** —— 与 `danci-admin/db/schema.ts` 的既有决策保持一致。后台删书时若加 FK+CASCADE，会连带删掉用户学习记录；若加 FK 无 CASCADE，又会因历史脏数据导致删书失败。保持弱关联，删书后进度行自然成为"孤儿数据"，由 `bookId` 查不到书时前端不展示即可。
2. **`lastWordRank` 冗余** —— 学习页需要"从最近单词的**下一个**开始"，有了 rank 就能直接 `WHERE wordRank > ?`，无需把整本书载入内存再线性查找。
3. **`lastWordId` 可空** —— 用户可能点进学习页但没看完就退出，此时不写进度比写一条"第 0 个"更干净。
4. **无 RLS** —— 本项目所有 DB 访问都经服务端 Drizzle（持有 service key），不走 Supabase 客户端直连，因此**不需要**开 RLS。`books`/`words` 是公共只读表，`user_*` 表不对外暴露，安全性由服务端守卫保证。> 若未来 H5 改为 Supabase JS 直连（客户端直查），则必须补 RLS，策略见 11.3。

### 3.4 `user_word_records` — 单词学习明细表

需求 v1 只要求"记住学到哪"，明细表不是必需；但它是**学习进度百分比、"已学 X/Y"、未来 SRS 算法的唯一数据来源**。现在建表的成本远低于以后补建（历史数据无法回溯）。

```sql
create table if not exists public.user_word_records (
  id            text primary key,                       -- "uwr-<base36>-<rand>"
  "userId"      text not null
                  references public.users(id) on delete cascade,
  "wordId"      bigint not null,                        -- words.id
  "bookId"      text not null,                          -- 冗余单词书，便于按书统计
  "wordRank"    integer,                                -- 冗余排名
  status        text not null default 'learning'
                  check (status in ('learning','known','unknown')),
  "studyCount"  integer not null default 1,             -- 累计学习次数
  "lastStudiedAt" timestamptz not null default now(),
  "createdAt"   timestamptz not null default now(),
  updated_at    timestamptz not null default now(),

  constraint user_word_records_user_word_uniq unique ("userId", "wordId")
);

-- 按书统计已学数量：WHERE userId = ? AND bookId = ? AND status = 'known'
create index if not exists user_word_records_user_book_status_idx
  on public.user_word_records ("userId", "bookId", status);
```

**`status` 语义**（v1 全部写 `'learning'`，为 SRS 预留）

| 值 | 含义 | 何时写入 |
| --- | --- | --- |
| `learning` | 学习中 / 刚接触 | v1：每次「下一个」都写这个 |
| `known` | 已掌握 | v2：接入 SRS 算法或用户主动标记 |
| `unknown` | 不认识 | v2：预留 |

**`bookId` 冗余的理由**：`user_word_progress` 的百分比要按书统计，而 `words` 关联是弱引用；把 `bookId` 冗余到明细表后，统计一次索引扫描即可，无需 join。

### 3.5 ER 关系

```text
users ──┬──< user_book_progress >──（弱引用）── books ──（弱引用）── words
        │                                    ↑ bookId          ↑ id
        └──< user_word_records >──────────────────────────┘
                                    wordId
```

| 关系 | 类型 | 理由 |
| --- | --- | --- |
| `users` → `user_book_progress` | FK + CASCADE | 用户注销则进度无意义，级联清理 |
| `users` → `user_word_records` | FK + CASCADE | 同上 |
| `user_book_progress.bookId` → `books.bookId` | **无 FK** | 避免删书波及学习数据（3.3 要点 1） |
| `user_word_records.wordId` → `words.id` | **无 FK** | 同上；`words` 会被后台批量清理 |
| `user_word_records.bookId` → `books.bookId` | **无 FK** | 同上 |

### 3.6 表清单校验 SQL

```sql
-- 迁移后自检：确认索引都建上了
select indexname, indexdef from pg_indexes
where tablename in ('users','user_book_progress','user_word_records')
order by tablename, indexname;

-- 确认 users 邮箱无重复（lower 归一后）
select lower(email) as e, count(*) from public.users
group by 1 having count(*) > 1;   -- 期望 0 行
```

## 4. Drizzle Schema 与迁移

### 4.1 新增 `db/index.ts`

沿用 `danci-admin/db/index.ts` 的**懒加载 Proxy + globalThis 单例**模式（务必照抄，这是 admin 踩过坑后的结论）：

```ts
import { drizzle } from "drizzle-orm/postgres-js";
import postgres from "postgres";

type PostgresClient = ReturnType<typeof postgres>;
type DrizzleDb = ReturnType<typeof drizzle>;

const globalForDb = globalThis as unknown as {
  __danciPg?: PostgresClient;
  __danciDrizzle?: DrizzleDb;
};

function getDb(): DrizzleDb {
  if (globalForDb.__danciDrizzle) return globalForDb.__danciDrizzle;

  const connectionString = process.env.POSTGRES_URL;
  if (!connectionString) {
    throw new Error("POSTGRES_URL is not set. 请在 .env 中配置 Supabase 连接串。");
  }

  const client =
    globalForDb.__danciPg ??
    postgres(connectionString, {
      prepare: false,        // PgBouncer 事务模式必需
      max: 2,                 // Serverless 严格控制连接数
      idle_timeout: 5,
      max_lifetime: 30,
      ssl: "require",
    });

  const db = drizzle(client);
  globalForDb.__danciPg = client;
  globalForDb.__danciDrizzle = db;
  return db;
}

export const db = new Proxy({} as DrizzleDb, {
  get(_target, prop) {
    const real = getDb() as unknown as Record<PropertyKey, unknown>;
    const value = real[prop];
    return typeof value === "function" ? value.bind(real) : value;
  },
});
```

### 6.1 改造 `app/auth.config.ts`

删除全局重定向，改为白名单保护（见 1.4）：

```ts
import type { NextAuthConfig } from "next-auth";

/** 需要登录才能访问的路由前缀 */
const PROTECTED_PREFIXES = ["/study", "/word"];

export const authConfig = {
  pages: { signIn: "/login" },
  providers: [],
  callbacks: {
    authorized({ auth, request: { nextUrl } }) {
      const { pathname } = nextUrl;
      const needsAuth = PROTECTED_PREFIXES.some((p) => pathname.startsWith(p));
      if (needsAuth && !auth?.user) return false;
      return true;
    },
  },
} satisfies NextAuthConfig;
```

> 需求要求"未登录点击单词书 → 跳 `/me` 并弹登录"。由于 `/me` 不在白名单，游客可正常访问 `/me`，由页面自己判断是否弹窗。`/study` 在白名单，未登录直接访问会被 NextAuth 拦到 `/login`——这是兜底，正常流程下用户不会直接敲这个 URL。

### 6.2 改造 `app/auth.ts`

关键是补 `jwt` / `session` 回调，把 `user.id` 透传出来（默认 Credentials + JWT 策略下，`session.user.id` 是 `undefined`）：

```ts
import NextAuth from "next-auth";
import Credentials from "next-auth/providers/credentials";
import { compare } from "bcryptjs";
import { findUserByEmail } from "@/lib/user-repo";
import { authConfig } from "@/app/auth.config";

export const { handlers: { GET, POST }, auth, signIn, signOut } = NextAuth({
  ...authConfig,
  session: { strategy: "jwt" },
  providers: [
    Credentials({
      name: "email",
      credentials: {
        email: { label: "邮箱", type: "email" },
        password: { label: "密码", type: "password" },
      },
      async authorize({ email, password }) {
        if (typeof email !== "string" || typeof password !== "string") return null;
        const user = await findUserByEmail(email.trim());
        if (!user) return null;
        const ok = await compare(password, user.passwordHash);
        if (!ok) return null;
        // 只返回必要字段，passwordHash 绝不进 session
        return { id: user.id, email: user.email, name: user.email.split("@")[0] };
      },
    }),
  ],
  callbacks: {
    ...authConfig.callbacks,
    jwt({ token, user }) {
      if (user?.id) token.uid = user.id;      // 登录时写入
      return token;
    },
    session({ session, token }) {
      if (token.uid) session.user.id = token.uid as string;  // 每次会话透出
      return session;
    },
  },
});
```

### 6.5 Server Actions：`app/actions/auth-actions.ts`

复用现有 `signIn` / `createUser` 语义，但改为弹窗场景（**注册成功直接登录，不再 redirect 到 `/login`**）：

```ts
"use server";

import { redirect } from "next/navigation";
import { signIn } from "@/app/auth";
import { hashPassword } from "@/lib/password";
import { createUser, EmailAlreadyExistsError } from "@/lib/user-repo";
import { MIN_PASSWORD_LENGTH } from "@/lib/constants";

export interface AuthState {
  error?: string;
  fieldErrors?: { email?: string; password?: string };
}

export async function loginAction(
  _prev: AuthState,
  formData: FormData,
): Promise<AuthState> {
  const email = String(formData.get("email") ?? "").trim();
  const password = String(formData.get("password") ?? "");

  if (!email) return { fieldErrors: { email: "请输入邮箱" } };
  if (!password) return { fieldErrors: { password: "请输入密码" } };

  try {
    await signIn("credentials", { email, password, redirectTo: "/" });
    return {};
  } catch {
    // NextAuth v5 credentials 失败时抛 AuthError
    return { error: "邮箱或密码不正确" };
  }
}

export async function registerAction(
  _prev: AuthState,
  formData: FormData,
): Promise<AuthState> {
  const email = String(formData.get("email") ?? "").trim();
  const password = String(formData.get("password") ?? "");

  const fieldErrors: AuthState["fieldErrors"] = {};
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) fieldErrors.email = "邮箱格式不正确";
  if (password.length < MIN_PASSWORD_LENGTH) {
    fieldErrors.password = `密码至少 ${MIN_PASSWORD_LENGTH} 位`;
  }
  if (Object.keys(fieldErrors).length > 0) return { fieldErrors };

  try {
    const passwordHash = await hashPassword(password);
    await createUser({ email, passwordHash });
    // 注册成功直接登录，省掉一次手动登录
    await signIn("credentials", { email, password, redirectTo: "/" });
    return {};
  } catch (err) {
    if (err instanceof EmailAlreadyExistsError) {
      return { fieldErrors: { email: "该邮箱已注册，请直接登录" } };
    }
    console.error("[registerAction]", err);
    return { error: "注册失败，请稍后再试" };
  }
}

export async function logoutAction() {
  await signOut({ redirectTo: "/" });
}
```

> **`useActionState` vs `useFormState`**：`next@14.0.4` 对应 React 18，Server Actions 的表单状态 hook 是 **`useFormState`**（来自 `react-dom`），`useActionState` 是 React 19 的 API。本项目锁定 React 18，**必须用 `useFormState`**：
> ```tsx
> "use client";
> import { useFormState, useFormStatus } from "react-dom";
> const [state, formAction] = useFormState(loginAction, {});
> ```

```tsx
"use client";

import { useState, useTransition } from "react";
import { useRouter } from "next/navigation";

interface StudyCard {
  wordId: string;
  wordRank: number;
  headWord: string;
  usphone: string | null;
  ukphone: string | null;
  firstTranCn: string | null;
}

export function WordCard({ cards, startIndex, total, bookId }: {
  cards: StudyCard[];
  startIndex: number;
  total: number;
  bookId: string;
  saveProgress: (fd: FormData) => void;
  touchWord: (fd: FormData) => void;
}) {
  const [i, setI] = useState(0);
  const [isPending, startTransition] = useTransition();
  const router = useRouter();
  const card = cards[i];
  const isLast = i === cards.length - 1;

  function next() {
    if (isLast) {
      // 完成本课：写回进度后回首页
      const fd = new FormData();
      fd.set("bookId", bookId);
      fd.set("lastWordId", card.wordId);
      fd.set("lastWordRank", String(card.wordRank));
      startTransition(async () => {
        await saveProgress(fd);
        router.push("/");
      });
      return;
    }
    // 记录当前单词已学
    const fd = new FormData();
    fd.set("wordId", card.wordId);
    fd.set("bookId", bookId);
    fd.set("wordRank", String(card.wordRank));
    startTransition(async () => { await touchWord(fd); });
    setI((v) => v + 1);
  }

  return (
    <div className="flex flex-1 flex-col justify-center">
      <p className="text-center text-sm text-slate-400">
        第 {startIndex + i + 1} / {total} 个
      </p>

      <div className="mt-16 text-center">
        {/* 单词本体 */}
        <p className="text-5xl font-semibold tracking-tight">{card.headWord}</p>
        {/* 音标 */}
        {card.usphone ? (
          <p className="mt-3 text-lg text-slate-500">/{card.usphone}/</p>
        ) : null}
        {/* 只展示一条中文释义 */}
        {card.firstTranCn ? (
          <p className="mt-10 text-2xl text-slate-800">{card.firstTranCn}</p>
        ) : null}
      </div>

      <div className="mt-auto flex gap-3 pb-6">
        <a
          href={`/word/${bookId}/${card.wordId}`}
          className="flex-1 rounded-xl border border-slate-200 bg-white py-3 text-center text-sm text-slate-600"
        >
          查看详情
        </a>
        <button
          onClick={next}
          disabled={isPending}
          className="flex-1 rounded-xl bg-blue-600 py-3 text-sm font-medium text-white disabled:opacity-50"

          {isLast ? "完成本课" : "下一个 ›"}

      </div>
    </div>
  );
}
```

### 8.3 Server Action 的鉴权（不可省略）

Server Action 是**公开的 HTTP 端点**，前端不显示按钮 ≠ 不能被调用。每个 action **必须**在函数体首行自查：

```ts
"use server";

export async function saveProgressAction(formData: FormData) {
  const user = await currentUser();
  if (!user) throw new Error("UNAUTHORIZED");       // ← 关键
  const bookId = String(formData.get("bookId") ?? "");
  const lastWordId = String(formData.get("lastWordId") ?? "");
  if (!bookId || !lastWordId) throw new Error("BAD_REQUEST");
  await saveProgress({ userId: user.id, bookId, lastWordId, /* ... */ });
}
```

**`userId` 必须从 session 取，绝不能从 `formData` 取**——否则用户可以伪造别人的 `userId` 写入进度。

## 9. 类型定义

`lib/word-content.ts` —— 把松散的 JSON 收敛成强类型，并把 `syno.hwds[].w` / `relWord.words[].hwd` 的差异固化下来：

```ts
/* ============ 原始 JSON 结构（宽松） ============ */

interface RawWordContent {
  word?: {
    wordHead?: string;
    wordId?: string;
    content?: {
      usphone?: string | null;
      ukphone?: string | null;
      usspeech?: string | null;
      ukspeech?: string | null;
      trans?: { tranCn?: string; tranOther?: string }[];
      sentence?: { sentences?: { sContent?: string; sCn?: string }[] };
      phrase?: { phrases?: { pContent?: string; pCn?: string }[] };
      syno?: { synos?: { pos?: string; tran?: string; hwds?: { w?: string }[] }[] };
      relWord?: { rels?: { pos?: string; words?: { hwd?: string; tran?: string }[] }[] };
    };
  };
}

/* ============ 归一化后（严格，UI 直接消费） ============ */

export interface ParsedWord {
  wordId: string;
  wordHead: string;
  usphone: string | null;
  ukphone: string | null;
  usspeech: string | null;
  ukspeech: string | null;
  trans: { tranCn: string; tranOther: string | null }[];
  sentences: { sContent: string; sCn: string | null }[];
  phrases: { pContent: string; pCn: string | null }[];
  synos: { pos: string; tran: string | null; words: string[] }[];      // 归一为 string[]
  relWords: { pos: string; words: { hwd: string; tran: string | null }[] }[];
}

export function parseWordContent(raw: unknown, fallbackHead?: string): ParsedWord | null {
  const root = (raw ?? {}) as RawWordContent;
  const w = root.word;
  const c = w?.content;
  if (!w?.wordId) return null;

  const str = (v: unknown) =>
    typeof v === "string" && v.trim().length > 0 ? v.trim() : null;

  return {
    wordId: w.wordId,
    wordHead: str(w.wordHead) ?? fallbackHead ?? w.wordId,
    usphone: str(c?.usphone),
    ukphone: str(c?.ukphone),
    usspeech: str(c?.usspeech),
    ukspeech: str(c?.ukspeech),
    trans: (c?.trans ?? [])
      .map((t) => ({ tranCn: str(t.tranCn) ?? "", tranOther: str(t.tranOther) }))
      .filter((t) => t.tranCn.length > 0),
    sentences: (c?.sentence?.sentences ?? [])
      .map((s) => ({ sContent: str(s.sContent) ?? "", sCn: str(s.sCn) }))
      .filter((s) => s.sContent.length > 0),
    phrases: (c?.phrase?.phrases ?? [])
      .map((p) => ({ pContent: str(p.pContent) ?? "", pCn: str(p.pCn) }))
      .filter((p) => p.pContent.length > 0),
    // 近义词：hwds[].w → 拍平成 string[]
    synos: (c?.syno?.synos ?? []).map((s) => ({
      pos: str(s.pos) ?? "",
      tran: str(s.tran),
      words: (s.hwds ?? []).map((h) => str(h.w) ?? "").filter(Boolean),
    })).filter((s) => s.words.length > 0),
    // 同根词：words[].hwd —— 注意不是 hwds
    relWords: (c?.relWord?.rels ?? []).map((r) => ({
      pos: str(r.pos) ?? "",
      words: (r.words ?? [])
        .map((w) => ({ hwd: str(w.hwd) ?? "", tran: str(w.tran) }))
        .filter((w) => w.hwd.length > 0),
    })).filter((r) => r.words.length > 0),
  };
}
```

`db/schema.ts` 已导出 `BookRow` / `WordRow` 等 Row 类型，仓储层返回时统一转为 `string` 化的 View 类型，避免 `Date` / `BigInt` 泄漏到 RSC 边界。

## 10. 性能设计

### 10.1 学习页：只取需要的字段（最大优化点）

一本单词书有 130+ 词，每条 `content` JSON 约 2–5 KB。**若把整本书的 `content` 传到客户端，首屏可能超过 500 KB**。

对策：学习页 SQL 里用 `#>>` 只取 6 个标量字段（第 5.3 节 `listStudyCards`）：

| 做法 | 单书传输量 |
| --- | --- |
| ❌ `select * from words where bookId=?` | 约 400–600 KB |
| ✅ `#>>` 取 6 个字段 | 约 8–15 KB |

**取 200 条上限**的原因：单次学习会话通常不超过 50 词，预留 4 倍冗余；`LIMIT` 保证即使遇到 144 词的书也不会一次性拉爆。学到末尾时前端可再请求下一批（v1 未实现，因为大部分书都够用）。

### 10.2 绕开 `json` 类型无法建 GIN 索引的限制

`words.content` 是 `json` 而非 `jsonb`，**无法** `CREATE INDEX ... USING gin (content)`，所以不能靠索引做"按释义搜索单词"这类查询。

v1 的应对：
- **所有单词查询都带 `bookId` 等值条件或 `id` 主键**，走 B-tree 索引，不依赖 JSON 索引。
- 若未来要做全文检索，方案是：① `ALTER TABLE words ALTER COLUMN content TYPE jsonb USING content::jsonb;`（在线、可回滚、需重写全表，建议低峰执行）；② 或建物化视图 `words_flat(headWord, bookId, tranCn)` + GIN。**本期不做**。

### 10.3 缓存策略

| 数据 | 策略 | 理由 |
| --- | --- | --- |
| `books` 列表 | `unstable_cache` / `revalidate = 3600` | 变动极少（只有后台增删改） |
| `words` 详情 | `revalidate = 86400` | 词典数据是静态的 |
| `user_*` 进度 | **不缓存**，`dynamic = 'force-dynamic'` | 每个用户不同，且要求实时 |

```ts
// lib/word-repo.ts
export const listBookList = unstable_cache(
  async () => { /* ... */ },
  ["book-list"],
  { revalidate: 3600, tags: ["books"] },
);
```

### 10.4 连接池

必须照抄 admin 的配置（`max: 2` + `idle_timeout: 5` + `max_lifetime: 30` + `prepare: false`）。Supabase PgBouncer 事务模式下每个 lambda 只应持有 1–2 条连接，否则会触发 `Max client connections reached`。

### 10.5 移动端性能

- 用 `min-h-[100dvh]` 而非 `100vh`（解决 iOS Safari 地址栏遮挡）。
- 底部 Tab 用 `env(safe-area-inset-bottom)` 适配全面屏。
- 单词卡片不加载任何图片/字体资源，单卡渲染 < 16ms。
- 不用图标字体、不用 UI 组件库（admin 用的 shadcn/ui 对 H5 是过重的包体）。

## 11. 安全设计

### 11.1 认证安全

| 项 | 措施 |
| --- | --- |
| 密码存储 | bcrypt（`bcryptjs`，rounds=10），**绝不明文、绝不存 session** |
| 密码列长 | `text`（不是 `VARCHAR(64)`），给算法升级留余量 |
| 邮箱唯一 | `unique` + `lower(email)` 唯一索引，防大小写绕过重复注册 |
| 邮箱存储 | 统一 `toLowerCase()` 后入库，登录时 `lower()` 比较 |
| 错误信息 | 登录失败统一返回"邮箱或密码不正确"，**不区分"邮箱不存在"与"密码错误"**，防用户枚举 |
| 注册竞态 | `createUser` 先查后插 + DB unique 约束双保险，捕获 `23505` 返回 409 |
| 会话 | NextAuth JWT 策略，`httpOnly` + `sameSite=lax` + 生产 `secure` |
| 登出 | 服务端销毁 session + 清 cookie |

### 11.2 授权安全

**分层原则**：判定"是不是你"永远在服务端，前端只做展示裁剪。

| 层级 | 措施 |
| --- | --- |
| 路由层 | `auth.config.ts` 的 `authorized` 保护 `/study`、`/word` |
| 页面层 | `currentUser()` 返回 `null` → 渲染登录弹窗 / `notFound()` |
| Action 层 | **每个 Server Action 首行 `currentUser()` 自查**（8.3 节） |
| 数据层 | 所有 `user_*` 查询都带 `where userId = session.uid`，**不接受外部传入的 userId** |
| 视图层 | `toView()` 剥掉 `passwordHash`，永不返回前端 |

### 11.3 RLS 策略（当前不需要，但备案）

本项目所有 DB 流量都经服务端 Drizzle（service key），**不开 RLS**。若将来改为 Supabase JS 客户端直连，必须补：

```sql
alter table public.users enable row level security;
alter table public.user_book_progress enable row level security;
alter table public.user_word_records enable row level security;

-- users：只能读写自己
create policy "users_select_own" on public.users
  for select using (id = auth.uid()::text);
create policy "users_update_own" on public.users
  for update using (id = auth.uid()::text);

-- 进度与明细：只能读写自己的
create policy "ubp_own" on public.user_book_progress
  for all using ("userId" = auth.uid()::text)
  with check ("userId" = auth.uid()::text);
create policy "uwr_own" on public.user_word_records
  for all using ("userId" = auth.uid()::text)
  with check ("userId" = auth.uid()::text);

-- books / words 是公共只读表，如需开放给客户端则单独放开 select
```

> 注意：`users.id` 是 text，`auth.uid()` 返回 uuid，**必须 `::text` 强转**，否则类型不匹配报错。

### 11.4 输入校验

| 输入 | 校验 | 位置 |
| --- | --- | --- |
| 邮箱 | 正则 + `toLowerCase` + DB unique | Server Action |
| 密码 | 长度 ≥ `MIN_PASSWORD_LENGTH`(8) | Server Action |
| `bookId` | 路由参数，只用于查库，不拼进 SQL（Drizzle 参数化） | 页面层 |
| `wordId` | `BigInt()` 转换失败即视为非法 | 仓储层 |

Drizzle 全程使用参数化查询，**不存在 SQL 注入面**。唯一要注意的是 `db.execute(sql\`...\`)` 手写 SQL 时必须用 `${}` 插值而非字符串拼接——本文所有手写 SQL 均已正确插值。

### 11.5 XSS 与内容安全

单词 `content` 来自外部词库（金山/有道导出），**内容不可信**。React 默认转义文本节点天然防 XSS，但：
- 严禁对 `tranCn` / `sContent` 等使用 `dangerouslySetInnerHTML`。
- 例句中若需高亮 `<b>` 标记，必须先经白名单净化。
